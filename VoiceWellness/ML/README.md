# Классификатор акустических окон кашля

Прототип бинарного классификатора «кашель / прочее». 101 признак из односекундного моно на 16 кГц: 24 log-mel полосы (среднее, стандартное отклонение и 90-й процентиль по активным кадрам, среднее абсолютное изменение по всем кадрам), затем пять скалярных признаков из функции `features`. Логистическая регрессия. Признаки и порядок описаны непосредственно в `train_cough.py`. Core ML принимает вектор признаков, возвращает логит. Длительный аудиопоток обрабатывает скрипт `predict_cough.py`, который применяет сигмоиду, порог из отчёта и объединяет перекрывающиеся окна. Этот экспериментальный экспорт Core ML отделён от общей мобильной модели ниже.

## Запуск

Python 3.9, FFmpeg в PATH и macOS с Core ML для проверки экспорта. Установить зависимости из `requirements.txt`.

```sh
python predict_cough.py /path/to/recording.wav
python train_cough.py /path/to/data /path/to/new-results
```

## Источники и воспроизводимость

- [FSD50K](https://zenodo.org/records/4060432). Скачать ZIP с метками как `fsd_truth.zip`, метаданные как `fsd_meta.zip`, затем запустить `python fetch_fsd.py /path/to/data`. Скрипт отбирает CC BY и CC0, читает нужные файлы из двух частей ZIP по HTTP Range и проверяет CRC. Точный фактически использованный набор и указание авторов в `results/fsd-attribution.csv`. Разделение по загрузчикам, метки на уровне клипа. Из-за ответов 429 часть выбранных клипов не скачалась.
- [COUGHVID v3](https://zenodo.org/records/7024894), CC BY 4.0. Поместить `public_dataset_v3.zip` в каталог данных как `coughvid.zip`. Выбраны записи с `cough_detected ≥ 0.95`, где это исходная модельная оценка, а не ручная гарантия. Разделение по записям, идентификатора говорящего в расчёте нет.
- [AMI](https://groups.inf.ed.ac.uk/ami/corpus/), аудио CC BY 4.0, и [AMI Cough Annotations](https://github.com/paulleamy/AMI-Cough-Annotations). Поместить `Annotations_master.csv` как `ami.csv`, оригинальные Mix-Headset WAV как `ami/<meeting-id>.wav`. Использован для независимого теста на размеченных окнах. Список встреч и записей в `results/split-manifest.csv`. Исходное аудио в проект не входит.

## Результат

Порог выбран на отложенной части FSD50K. На тесте FSD50K — 13 из 15 положительных клипов и 8 ложных срабатываний на 14 отрицательных. На AMI — 31 из 49 положительных окон и 16 ложных на 135 отрицательных. На COUGHVID — 49 из 50 положительных клипов. Последний результат измеряет только долю обнаруженных позитивов. Полные метрики в `results/evaluation.json`.

Проверка на непрерывном отрезке AMI EN2001a, секунды 3126–3150: два соседних размеченных кашлевых толчка объединены в один интервал, найдено семь интервалов. Остальные шесть не совпали с положительной разметкой. Это проверка запуска на одном фрагменте, а не оценка ложных тревог в час. Для выбора детектора в приложении нужен общий событийный тест с Apple Sound Analysis и записи с iPhone и AirPods.

## Общая мобильная модель

iOS и Android используют один исходник DSP и один набор весов в `../App/MobileCough`. Анализ выполняется локально. Модель ищет вероятный кашель в окнах по 1 секунде с шагом 0,25 секунды и объединяет перекрывающиеся положительные окна. Выход для записи короче секунды отсутствует. Для Android-сборки нужны NDK 27.0.12077973 и CMake 3.22.1. Xcode подключает C через bridging header.

```sh
python train_mobile_cough.py /path/to/data ../App/MobileCough/CoughWeights.h results/mobile-evaluation.json
```

Обучение использует размеченные интервалы AMI и положительные примеры COUGHVID с меньшим весом. Встречи AMI разделены между обучением, подбором порога и тестом. Порог калибруется по максимуму среди окон в трёхсекундном клипе, как при оценке целого клипа. Отрицательные клипы с размеченным кашлем внутри окна исключаются. В `results/mobile-evaluation.json` записаны списки встреч и результаты по клипам. Эти результаты не измеряют число ложных срабатываний за час непрерывной записи и не подтверждают качество на физических телефонах. Сохранённые ранее результаты Apple Sound Analysis видны в отдельных замерах iOS, недельная частота считается по текущей модели.
